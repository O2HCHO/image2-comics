# 漫画上色工作台

Windows 10 / 11 64 位桌面应用：批量为漫画页上色，支持配色参考图、原图与结果对照、失败重试和断点续跑。

## 直接使用

完整解压 `dist/Image2Comics-1.4.0-Windows-x64.zip`，双击 `Image2Comics/Image2Comics.exe`。无需安装 Python。请保留同目录的 `_internal` 文件夹。

1. 在“接口与上色设置”填写服务地址、API Key、模型。OpenAI 兼容图像编辑地址需以 `/images/edits` 结尾，模型也可以手动填写。
2. 使用默认保真提示词，或自行修改。可选择多张已上色参考图；服务必须支持 `image[]` 多图编辑。第一张上传原稿，其余仅用于配色参考，不自动退回单图或更换协议。
3. 在工作台选择输入、输出目录，默认递归扫描。支持 PNG、JPG、JPEG、WebP、BMP，PDF 需先导出图片。列表使用 Ctrl / Shift 多选。
4. 点击“开始 / 继续上色”。处理按自然路径顺序串行执行，默认间隔 2 秒。选中当前页可对照预览，支持缩放与滚动；预览最长边上限 2400 像素，不影响输出。
5. 失败后点击“重试失败项”，或仅选中需要的图片再次开始。成功且校验通过的同配置结果会跳过。

API 上色需要联网和有效服务额度；模型可能改变文字、分镜或人物细节，请目视抽查。1.4.2 起上色输出锁定原稿长宽比，旧设置中的固定比例补边选项自动回到原稿比例。请求自动附加原稿尺寸及比例约束；GPT Image 2/2.5 模型同时发送符合服务像素网格的尺寸参数，其他服务不额外发送未知字段。服务仍可能返回不同尺寸，保存前会使用 Lanczos 重新采样校正，不裁切、不补边，并以整数交叉乘法验证比例完全相同。

输出尺寸按原稿宽高的最大公约数确定合法整数网格，选择最接近生成图像素面积且不低于原稿尺寸的一组宽高。因此不是分别四舍五入两条边，也不强制所有图片降到原稿分辨率。例如原稿 695×1080、生成图 1041×1510，无文字融合时校正为 973×1512，长宽比严格相同；若生成图为 1390×2160，则保持该尺寸。重采样不能凭空恢复模型丢失的细节。开启文字保护时沿用原稿画布完成对齐与字形融合，原始服务响应保留在 raw 中用于排查，不把 raw 当成最终输出。

## 整批监修、单页修改与 PDF

1.5.0 起监修页提供“历史版本 / 采用旧版”：选择该页成功保存的版本，预览图片与提示词，再点击采用。切换会校验原稿和版本文件，不调用 API、不删除任何版本；重启及 PDF 导出使用当前采用版本。扫描、生成或本地修复运行中需先等待结束再切换采用版本。

“重新生成此页 / 加入队列”允许在上色期间继续翻页并添加其他页，按点击顺序串行生成。每项保存入队时的完整提示词、模型、参考图和配置；同页已在等待队列时拒绝重复添加。等待列表显示在单页监修面板，可清空等待项而不影响当前页；停止或关闭会清空等待项并等待当前请求保存。队列仅保存在本次运行内存中，重启不自动发起付费请求。某页失败后继续处理后续页，失败页保留之前采用版本。

“整批监修 / 单页修改”显示整个输入目录的成对缩略图，每组 8 页，滚动并翻组可遍历全部页面，未上色页保留占位。只加载当前组的缩略图，避免把整本漫画原图一次性载入内存。点击某一组对照后，在右侧修改该页的完整提示词，再点击“仅重新生成这一页”；也可从工作台的“监修 / 改本页提示词”进入。

单页修订从原始漫画重新生成整页，沿用全局接口、模型和参考图，但不修改全局提示词。显式修订即使提示词相同也不跳过；成功后切换当前采用结果并更新预览和缩略图，失败保留上一版。旧文件和生成参数均保留，重启后恢复当前版本。尚未提交的提示词草稿可在切页时保留在内存中，关闭应用后不保留。

“导出全部上色图为 PDF”按全部输入页的自然路径顺序导出每页当前采用的上色结果，与列表多选无关。不会重复收录历史版本；不收录未匹配到输入页的任意输出文件。有缺页时先确认是否仅导出已有页，结果损坏、哈希不符或原稿改变时停止并提示修复。每张图独占一页，保持原始宽高比，不裁切、不重采样、透明转白底，图像无损嵌入。PDF 写入临时文件，成功后原子替换目标；导出失败保留既有 PDF。PDF 页面物理尺寸按 144 dpi 换算，图片像素不变。

支持升级旧版任务清单。没有任务记录的旧 `colored_原文件名` 文件可按相对目录自动匹配；若同名不同格式导致歧义，则不自动采用。普通批次续跑不会把已采用的修订版切回旧版本。

## 任务与文件保护

### 文字保护与本地修复

默认开启原稿文字保护，随包附带 comic-text-detector（CTD）和 YOLO 气泡 ONNX 模型，CPU 离线运行，无需首次联网下载，无 PyTorch 运行依赖。CTD 分块提取文字块、文字行和像素掩码；YOLO 定位气泡及旁白框，再验证实际封闭轮廓、墨线边界和文字归属。开放、无框及归属不明的文字自动跳过，艺术字与漏检可人工补选。严格筛选优先避免误处理画面，不保证覆盖全部对白。

生成图保存后，通过尺寸还原、多尺度 SIFT、RANSAC 相似变换及全局双向边缘/局部边缘检查，估计缩放、裁切和轻微旋转。宽高比变化不足15%时也尝试分别还原横纵尺寸，仍须通过同样的线条匹配检查。不通过时保留原始生成图并标记“文字需核对”，不采用未经保护的新图。文字融合输出使用原稿坐标与尺寸，未被上色图覆盖的外围采用原稿，采用前再次校验原稿比例。

文字编辑器对齐失败时，右侧仍显示原始上色图，并提供“查看原因与修复方法”：包括两图尺寸、最佳匹配评分、不通过的区域和处理步骤。外扩/羽化只调整字形，不解决构图错位；仅局部有问题时可取消该处保护后重新预览，整页构图改变时需要返回监修页重新生成（调用 API）。点击“保存并修复此页”时若尚未预览当前区域与参数，会先生成预览；请目视核对后再次点击保存。失败时窗口保持打开。

不再贴回整矩形或整个气泡。生成图先在气泡安全内部局部清除文字，再沿原稿笔画包络恢复文字前景与抗锯齿透明度，保留生成图底色。字形外扩、羽化默认各 1 个原稿像素，均受安全内部限制。复杂底纹、文字粘连边线及不可靠对齐标记为“文字需核对”。编辑器显示蓝色气泡轮廓、绿色文字框、橙色跳过候选，并可切换红色文字恢复/清字掩码；清字范围需先生成融合预览。

监修页可“本地修复当前页文字”或“本地修复全部已有结果”，完全不调用生成 API。每页先校验原稿及已有结果，成功原子切换当前版本，失败保留旧版。人工补选可覆盖框外文字，仍按字形处理，不贴回矩形白底。明确没有可处理文字时使用零掩码；气泡内疑似漏字需核对。旧版自动掩码重新检测，原稿未变化时保留人工编辑、参数及排除区域。缺少原始生成图且已有融合痕迹时拒绝修复，不能从旧白框可靠恢复底色。

`.comic-color/raw` 保存未经融合的生成图；`text` 保存模型版本、原稿指纹、检测及人工区域；`masks` 保存采用的灰度掩码，任务清单记录对齐评分。参数与区域纳入任务身份；原稿变化使旧缓存与人工区域失效。文字需核对的相同任务不会自动再次调用生成 API，应使用本地修复。单页“重新生成”仍表示明确发起新的付费生成。

模型 SHA-256 固定并加载校验，来源、上游版本和导出对比结果见 `assets/models/manifest.json`；许可证见 `THIRD_PARTY_NOTICES.txt` 与 `licenses/`。本版本按 AGPL-3.0 分发，随 Windows 包附对应应用源码 ZIP。文字检测和融合仍需抽查漏检、误检、错字残影和接缝。

- 默认单张最长等待 300 秒；不自动重发生成请求。超时不表示服务一定未计费，请确认后手动重试。
- 暂停、停止、关闭均等待当前请求完成并保存。关闭窗口确认后自动等待，无需再次操作。
- 任务记录位于输出目录的 `.comic-color/tasks.json`。记录原图内容指纹、参数、参考图指纹、结果校验值和状态，不记录 API Key。
- 中断时的“处理中”恢复为“待确认”，需要显式确认重试。恢复时校验原稿、所有参数及结果文件；图片丢失、损坏或内容变化会重新处理。
- 输出保留目录结构，统一 PNG，文件名含输入扩展名及任务标识。同名不同格式、不同设置不会覆盖；已有文件另存新名称。原图保持不变。
- 输入目录与输出目录不能相同，输出目录不能是输入目录的上级；扫描会排除嵌套的输出目录。输出目录加排他锁，避免两个应用同时写入任务。
- 同一个输出目录只建议用于同一漫画库。任务清单损坏时停止，换输出目录或先备份清单后再修复。
- 成功/失败列表状态为最近一次历史记录；点击开始时才校验是否能复用。更换模型、提示词或参考图将生成新任务变体。

## 配置与兼容

设置、轮转日志位于 `%LOCALAPPDATA%/Image2Comics`。仅主动勾选“记住 API Key”时使用 Windows DPAPI 加密保存，可取消勾选并保存以清除。旧项目 `local_settings.json` 首次只迁移非敏感配置，旧密钥需重新输入；原文件不改动。发布包不包含个人配置和图片。

保留 OpenAI multipart 编辑和自定义 Base64 JSON 两种模式。JSON 模式发送 `model`、`image`、`prompt`、`denoising_strength`，不支持参考图。multipart 不发送重绘幅度。响应兼容 `image`、`images[0]`、`data.image`、`data.images[0]`、`data[0].b64_json`、图片 URL 和 Data URL。结果下载不携带 API Authorization。API 请求不跟随重定向。

`bili_comic` 仍独立使用，直接选择其 `coloring_input` 导出目录即可。

## 开发与构建

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe app.py
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe build.py
```

构建脚本先生成图标、运行测试，再以 PyInstaller 文件夹模式打包并生成 ZIP。依赖版本已固定；也可通过 `environment.yml` 创建 Conda 运行环境。

模型已随源码包提供，普通运行及打包不需要下载。重新准备模型时，在独立 Python 环境安装 `requirements-models.txt`，先运行 `tools/download_comic_assets.py`，再运行 `tools/prepare_comic_models.py`。后者导出气泡 ONNX、对比 PyTorch/ONNX 原始输出及候选类别并记录指纹。已交付权重实际导出环境记录在 manifest 中；其他环境重新导出可能产生不同二进制指纹，需审核验证并同步固定指纹后才能分发。`tools/check_comic_models.py` 仅使用现有图片，在 `build/comic-qa` 输出对照与 CPU 性能报告，绝不请求生成 API。

项目目录：

| 路径 | 用途 |
| --- | --- |
| `app.py` | 桌面应用入口与离线诊断入口 |
| `comic_color/` | 界面、项目管理、API、批次任务、监修、文字保护及 PDF 导出 |
| `assets/` | 图标、离线 ONNX 模型及模型来源与指纹 |
| `tests/` | 自动化测试 |
| `tools/` | 模型准备、图标生成及手动验收工具 |
| `licenses/`、`THIRD_PARTY_NOTICES.txt` | 第三方许可证与声明 |
| `build.py`、`Image2Comics.spec` | Windows 打包入口与 PyInstaller 配置 |
| `requirements*.txt`、`environment.yml` | 运行、开发及模型导出环境 |
| `build/`、`dist/` | 本地构建中间文件与可分发压缩包，不提交到 Git |
| `inputs/`、`outputs/`、`local_settings.json` | 本地图片、生成结果及个人配置，不提交到 Git |

核心模块：`comic_color/gui.py` 管理界面和后台事件；`api.py` 适配服务；`jobs.py` 管理任务、锁及恢复；`imaging.py` 负责图片；`config.py` 负责原子存储和密钥。克隆仓库包含运行所需的离线模型；Windows ZIP 需在本地运行 `build.py` 生成。

离线端到端诊断（会短暂显示窗口；不请求真实服务；设置隔离）：

```powershell
.\.venv\Scripts\python.exe app.py --self-test build\source-smoke
build\dist-1.4.0\Image2Comics\Image2Comics.exe --self-test build\frozen-smoke
```

报告及截图保存到指定目录，查看 `report.json` 的 `success`。覆盖窗口启动、模型列表、多图上传、预览、任务结果、恢复跳过、设置加密和打开目录回调。测试不会真的打开资源管理器窗口。

`tools/live_check.py` 是显式的真实服务验收脚本，会读取旧配置中的密钥，仅在内存使用，并发送一张原稿和一张既有参考图，会消耗额度。不要将它用于离线测试或反复请求；结果写入 `outputs/integration-check`。

### 1.3.1 单页保留与大图监修

在列表中只选一页，点击“不需上色 / 输出原图”，或在监修中点击同名按钮，直接复制原图到结果并在续跑时跳过 API。重新生成此页可恢复上色。监修支持左右键翻页、滚轮滚动、拖拽与缩放，并预读邻页。文字保护收紧笔画置信度，拒绝跨气泡边界文字与长直线；旧检测缓存会自动失效，已有结果需手动本地修复后更新。

### 1.4.0 项目工作区与本地编辑加速

启动进入项目首页，不再自动扫描上次的漫画目录。选择“新建项目 / 接管旧漫画”，指定工作区、原图目录及已有结果目录（也可使用项目内的 results）。图片保留原位置；项目的 project.json 保存编辑设置，.comic-color 保存任务、索引、人工选区与缓存。一个结果目录仅由一个项目接管。

旧任务及“不需上色”选择在首次接管时导入，不修改旧任务清单和图片；旧自动文字掩码按需重建。打开项目先显示上次页面清单，再后台核对目录变化。API 地址、密钥、模型全局共用，提示词、参考图、比例、文字保护及监修位置按项目保存。项目目录移动后可重新定位原图与结果，已跟踪内容必须通过哈希校验。

文字检测只在打开该页文字编辑或实际处理时运行。融合缓存分为对齐、生成图文字检测与最终预览；调整外扩、羽化可复用中间结果。内容、模型、算法或相关参数改变会使对应缓存失效。缓存默认每项目最多 120 项、2 GiB。冷检测仍需要 CPU 推理；状态栏显示当前阶段，日志记录阶段耗时。上色、修复、导出写入时不能切换项目；扫描和预览的过期回调会被丢弃。
